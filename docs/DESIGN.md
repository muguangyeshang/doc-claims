# 设计文档

## 1. 问题定义

README/手册/地图里写的整数声明（"46 项检查"、"共 2987 个技能"）随代码演化漂移。单元测试拦不住——文档自己不会跑。doc-claims 把每类数字变成 CI 断言：**登记「正则模式 + 真值重算命令」，扫描活文档逐处与当场重算值比对**。

## 2. 核心数据流

```
扫描 files(glob) → 逐行匹配 types[].pattern（第一个捕获组=写的数字）
  → 行命中 exempt_patterns → 跳过（显式打印）
  → 真值 truth.cmd（输出第一个整数，按 spec 缓存）/ truth.literal
  → 写的 == 算的 ？ ✓ : ✗
全绿 exit 0；任一 ✗ exit 1；--strict 且 0 处核对 exit 1
```

## 3. 三条设计原则（与同类工具的差异所在）

1. **真值必须来自重算，不来自另一份文档。** 文档对文档只会把漂移复制一遍。真值源是任意 shell 命令——任何语言的项目都能接，引擎保持通用。
2. **豁免按整行、写在配置里。** 历史记录、旧文引用不是活声明。豁免词藏在代码里不可审计，写在 claims.json 里 diff 得到。
3. **静默降级比红更危险。** `--strict` 专防"模式写错 → 0 处核对 → 静默绿"——CI 变绿其实可能只是少查了一条。所有跳过路径都要显式打印。

## 4. 性能

真值按 spec 缓存：同一类数字 100 处命中只重算 1 次（`truth_value` 的 cache，key 是 spec 的规范化 JSON）。模式匹配是 O(行数 × 类型数)，纯 regex，无瓶颈。

## 5. 配置规范

| 字段 | 责任 | 约束 |
|---|---|---|
| `files` | 待扫文件 glob | 至少 1 个模式命中文件，否则报错退出（不静默） |
| `types[].pattern` | 数字声明模式 | 第一个捕获组必须是整数 |
| `types[].truth` | 真值源 | `cmd`（输出第一个整数）或 `literal` 二选一；cmd 失败/无数字 → ✗ 而非跳过 |
| `exempt_patterns` | 整行豁免 | 正则，行级匹配；默认建议含"历史记录""引用原文" |

**写 pattern 的经验**：让数字和量词紧挨着（`(\d+) 个测试`），中间插形容词会漏（"46 项**常驻**检查"曾漏过，改文档对齐了）；同一数字有多种写法就登记多个 type。

## 6. CI 集成

两种入口等价：
- **直接 CLI**：`python doc_claims.py --config claims.json --strict`（退出码即断言）
- **GitHub Action**：`uses: <you>/doc-claims@v1.0.0`（composite action 包同一条命令）

本仓库自己的 CI 包含"漂移必须红"步骤：故意改错文档数字、断言 exit 1——尺子自己会不会瞎也锁进 CI。
